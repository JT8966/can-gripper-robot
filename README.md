# หุ่นยนต์คีบกระป๋อง · MOTION:BIT Pro

กด **A** ให้รถค้นหากระป๋องและอ่านสีกระป๋องขวา เมื่อคีบแล้วจะแสดงสีขวา (`R`) บนจอ micro:bit กด **B** เพื่อหยุด

จัดราง S1 ไว้ที่ระดับรับกระป๋องก่อนเปิดเครื่อง วงคีบขวา S3 มีเซ็นเซอร์สี TCS34725 ต่อตรงเข้าบัส I2C (addr 0x29) โดยไม่ต้องผ่าน PCA9548A

- **ติดครบห้าดวง** เดินตรงตามเข็มทิศ ใช้ HC-SR04 วัดระยะเข้าหากระป๋อง
- **ดับหนึ่งถึงสี่ดวง** เบรกแล้วหมุนอยู่กับที่เข้าหาฝั่งที่ยังติด แม้กำลังเลี้ยวขวา 90° ก็เปลี่ยนมาแก้แนวทันที เมื่อครบห้าดวงจึงใช้ทิศใหม่เป็นแนวเดินตรง ถ้าสองฝั่งสมดุล เช่น ดับเฉพาะดวงกลาง ให้ใช้ทิศแก้ล่าสุด (เริ่มด้วยขวา) ถ้ายังติดไม่ครบภายใน 5 วินาทีในช่วงแก้แนวจะหยุดและขึ้น ✗
- **ดับทั้งห้าดวง** ถอยประมาณ 3 ซม. แล้วหมุนขวา 90° หากเริ่มเห็นบางช่องระหว่างหมุน ให้แก้แนวตามช่องที่ติดก่อนเดินต่อ

## ลงโปรแกรมครั้งแรก

### ถ้าจะเปลี่ยนพฤติกรรม ให้แก้ตรงไหน

**ตั้งค่าแขน** เปิด [main.py](./main.py) ในแท็บ Python ของ MakeCode แล้วแก้ตัวเลขหลังเครื่องหมาย `=` ตรงต้นไฟล์ จากนั้นกด **Download** อีกครั้ง ค่า 500 มิลลิวินาทีเท่ากับครึ่งวินาที

| พอร์ต | บรรทัดที่ค้นหาด้วย Ctrl+F | ค่าเริ่มต้น | ค่าที่ใส่ |
|---|---|---|---|
| S1 รางหมุนต่อเนื่อง | `RACK_UP_COMMAND` / `RACK_DOWN_COMMAND` | 75 / 105 | ทดสอบว่า 75 ทำให้เพลาหมุนซ้ายและยกรางจริง หากกลับทางให้สลับสองค่า ค่า 90 ใช้หยุด |
| S1 เวลายก / ลด | `RACK_UP_MS` / `RACK_DOWN_MS` | 500 / 500 ms | วัดเวลาจากระดับรับถึงท่าขน และจากท่าขนกลับถึงระดับวาง |
| S2 คีบซ้าย 180° | `GRIP_LEFT_OPEN` / `GRIP_LEFT_CLOSED` | 45° / 10° | กางไปทางซ้าย ใช้ 10° เป็นท่าหุบ |
| S3 คีบขวา 180° | `GRIP_RIGHT_OPEN` / `GRIP_RIGHT_CLOSED` | 45° / 10° | กางไปทางขวา ใช้ 10° เป็นท่าหุบ |

**ทดสอบแล้วสั่งหุบที่ 45° แต่หุ่นกลับกาง** จึงใช้ 45° เป็นท่ากางและ 10° เป็นท่าหุบทั้งสองข้าง หากฝั่งใดยังกางตอนสั่งหุบ ให้ไล่เพิ่มค่าหุบเฉพาะฝั่งนั้นทีละ 5° เพราะทิศที่วงเคลื่อนขึ้นกับการติดตั้งก้านเซอร์โวของแต่ละข้าง

**ถ้ากด B ขณะที่แขนกำลังรับ** ล้อและ S1 จะหยุด S2/S3 ค้างมุมล่าสุด ให้ประคองกระป๋อง จัดรางกลับระดับรับ แล้วกด **RESET** เพื่อเริ่มรอบใหม่

เปิด `main.py` แล้วกด **Ctrl+F** ค้นหาชื่อในตาราง ค่าที่ปรับกับหุ่นอยู่ต้นไฟล์ มุมปากคีบใช้หน่วยองศา เซอร์โว 360° ใช้ค่าควบคุมทิศและความเร็ว เวลารอใช้มิลลิวินาที ส่วนคำสั่ง `wait_micros` ของอัลตราโซนิกใช้ไมโครวินาที

| อยากเปลี่ยนอะไร | ค้นหาในโค้ด | วิธีปรับ |
|---|---|---|
| ให้รถเข้าใกล้กระป๋องอีกก่อนหยุด | `PICKUP_DISTANCE_CM` | เช่น เปลี่ยน 10 เป็น 8 เพื่อยืนยันการคีบภายใน 8 ซม. จากหน้าหัว HC-SR04 |
| ถอยไกลหรือสั้นลง | `REVERSE_3CM_MS` | เพิ่มเวลาถ้าอยากถอยไกลขึ้น แล้ววัดบนพื้นจริงอีกครั้ง |
| กำลังล้อ | `SPEED` | 255 คือเต็มกำลัง ค่านี้มีผลทั้งเดินหน้า ถอย และหมุน ถ้าแก้ให้วัดระยะถอยและมุมหยุดใหม่ |
| มุมเลี้ยวขวา | `TURN_DEG` | ตั้งเป็น 90 สำหรับมุมฉาก หรือ 60 สำหรับเลี้ยวขวา 60° ถ้ารถไหลเลยมุมที่ตั้ง ให้เพิ่ม `TURN_TOLERANCE_DEG` เพื่อเบรกเร็วขึ้น |
| ความไวในการรักษาแนวตรง | บรรทัด `amount =` และบรรทัด `trim +=` | 2 คือมุมเบนที่ยอมได้, 3 คือกำลังชดเชยต่อองศาที่เกิน, 80 คือเพดานส่วนต่างกำลัง ตัวเลข 16 ในบรรทัดถัด ๆ ไปจำกัดการเปลี่ยนต่อรอบ ลดขนาด 16 ทั้งสองฝั่งถ้าต้องการให้ค่อย ๆ ปรับขึ้นลง |
| ค้นหา อ่านสี และหนีบ | `find_cans` / `pick_cans` | ฟังก์ชันแรกตรวจ NB142, HC-SR04 และเข็มทิศ ฟังก์ชันที่สองอ่านสีจากหัวที่ตรงกับวงคีบแต่ละข้าง |

### นำเข้าและลงบอร์ด

1. เปิด [MakeCode สำหรับ micro:bit](https://makecode.microbit.org/) แล้วเลือก **Import → Import URL**
2. วางลิงก์ `https://github.com/JT8966/can-gripper-robot` แล้วกดนำเข้า
3. เสียบสาย USB ที่ส่งข้อมูลได้จากคอมพิวเตอร์ **เข้าพอร์ต USB บนตัว micro:bit** แล้วกด **Download** ใน MakeCode
4. ถ้าเบราว์เซอร์บันทึกไฟล์ `.hex` ลงคอม ให้คัดลอกไฟล์นั้นไปที่ไดรฟ์ **MICROBIT** แล้วรอไฟด้านหลังบอร์ดหยุดกะพริบ ถ้าจับคู่บอร์ดผ่าน WebUSB แล้ว ปุ่ม Download จะส่งโปรแกรมลงบอร์ดโดยตรง [คู่มือโอนโปรแกรมของ MakeCode](https://makecode.microbit.org/device/usb)

## พอร์ตของหุ่น

| อุปกรณ์ | พอร์ต MOTION:BIT Pro |
|---|---|
| ล้อซ้าย 2 ตัว | ต่อทีละตัวที่คู่ M1A/M1B และคู่ M2A/M2B ทิศเดินหน้าคือ M1A และ M2A |
| ล้อขวา 2 ตัว | ต่อทีละตัวที่คู่ M3A/M3B และคู่ M4A/M4B ทิศเดินหน้าคือ M3A และ M4A |
| รางยก–ลด (360° หมุนต่อเนื่อง) | S1 |
| วงคีบซ้าย (180°) | S2 |
| วงคีบขวา (180°) | S3 |
| HC-SR04 รุ่น 5V แบบ 4 ขา | VCC → ขา 5V, GND → GND, TRIG → P0, ECHO → P1 ผ่านตัวแบ่งแรงดัน |
| TCS34725 เซ็นเซอร์สีข้างขวา (มองกระป๋องขวา S3) | ต่อตรง I2C: SDA → P20, SCL → P19, VIN → 3V3, GND → GND (addr 0x29) |
| NB142 รุ่นเอาต์พุตดิจิทัล 5 ช่องที่รองรับ 3.3V | VCC → 3V3, GND → GND และเอาต์พุตซ้ายสุดถึงขวาสุด → P12, P13, P14, P15, P16 ที่ขา Signal ของ GPIO |

**ลดแรงดัน ECHO ก่อนต่อ P1** ต่อ ECHO → ตัวต้านทาน 10 kΩ → จุดร่วมที่ต่อเข้า P1 แล้วต่อจากจุดร่วมนั้นผ่านตัวต้านทาน 10 kΩ อีกตัวลง GND แรงดัน 5V จะลดเหลือประมาณ 2.5V [ผัง HC-SR04 สำหรับบอร์ด 3.3V](https://learn.adafruit.com/ultrasonic-sonar-distance-sensors/pinouts)

### ตั้งระยะและลำดับคีบ

คำสั่งเดินหน้าครั้งแรกส่งกำลัง 255/255 ไปยัง M1–M4 พร้อมกัน จากรอบถัดไปเข็มทิศจึงเริ่มชดเชยเมื่อรถเบน

- `PICKUP_DISTANCE_CM` คือค่า X วัดจากหน้าหัว HC-SR04 ตั้งไว้ **10 ซม. ชั่วคราว** วางกระป๋องที่ตำแหน่งหนีบจริงแล้วปรับค่านี้ หุ่นเบรกทันทีที่อ่านค่าใกล้ครั้งแรก และคีบเมื่อวัดซ้ำแล้วยังอยู่ในระยะ สัญญาณที่หมดเวลาจะไม่นับเป็นวัตถุ เซนเซอร์วัดได้ทั้งกระป๋องและวัตถุอื่นด้านหน้า
- ขณะเดินหน้า ล้อทั้งสี่หมุนไปข้างหน้า เมื่อทิศตรง รถใช้กำลัง 255/255 หากเบนเกิน 2° จะค่อย ๆ ผ่อนล้อด้านที่ต้องการเลี้ยวเข้าหา และคืนกำลังเมื่อกลับเข้าแนว กำลังสองฝั่งต่างกันได้สูงสุด 80 และปรับส่วนต่างครั้งละไม่เกิน 16 ตอนถอยล้อทั้งสี่ถอยพร้อมกัน ส่วนตอนหมุนขวา 90° ล้อซ้ายเดินหน้าและล้อขวาถอย
- `REVERSE_3CM_MS` คือเวลาถอย ตั้งต้น **50 มิลลิวินาที** ที่กำลังเต็ม ขีดจุดอ้างอิงแล้ววัดบนพื้นจริง เช่น ถ้าถอยได้ 2 ซม. ให้ลองปรับเป็น `50 × 3 / 2 = 75` มิลลิวินาที แล้ววัดซ้ำ
- เมื่อเปิดเครื่อง จอขึ้น ✓ แล้วแสดง A ค้างทันที โดยไม่แตะบัส I2C หรือเข็มทิศ ช่วงบูตจึงไม่ค้างหากเซ็นเซอร์หลุด กดปุ่ม A เพื่อเริ่มภารกิจ รถยังใช้ NB142 และเข็มทิศตามปกติ โดยปรับเทียบเข็มทิศเมื่ออ่านค่าครั้งแรกในรอบค้นหา เมื่อถึงระยะกระป๋องรถจะเบรกและตรวจหัวสีครั้งแรก ถ้ายังไม่พร้อม รถจอด ขึ้น ✗ และค้างวงคีบไว้ ดูผลได้ทาง USB Serial ถ้าค้นหานานเกิน 30 วินาที รถจะเบรก พิมพ์ `FIND TIMEOUT` ทาง Serial และขึ้น ✗
- เมื่อ HC-SR04 ยืนยันระยะสองครั้ง รถจอดแล้วอ่านสีกระป๋องขวาสองครั้งห่างกัน 65 มิลลิวินาที ถ้าอ่านได้สีเดิม รถจะสั่งหนีบ รอ 550 มิลลิวินาที แล้วยก S1 สีที่รองรับคือแดง เขียว และเหลือง (โค้ดยังอ่านน้ำเงินได้แต่กติกาไม่มี) ปรับเกณฑ์กับผิวกระป๋องและแสงจริงใน `read_color()`
- เมื่อคีบสำเร็จ รถวิ่งตาม `DELIVER_ROUTE[สี]` ไปแท่นเก็บสีเดียวกัน ยก S1 ตาม `PLACE_RAISE_MS[สี]` ให้พ้นขอบแท่น (เขียว 50 / เหลือง 100 / แดง 150 มม.) เปิดวงคีบปล่อยกระป๋องลงหลุม รอลดรางกลับ แล้ววิ่ง `RETURN_ROUTE[สี]` กลับจุดรับเพื่อรับชิ้นถัดไป ทำซ้ำจนครบ 6 ชิ้น

### ภารกิจเต็มตามกติกา อปท.

- หนึ่งรอบใช้เวลาแข่ง 3 นาที โค้ดรักษาเวลาไว้ `MATCH_MS = 180000` และหยุดเริ่มทริปใหม่เมื่อเหลือน้อยกว่า `MATCH_MARGIN_MS = 45000` เพื่อกันเวลาไว้เดินกลับ FINISH
- ลำดับใน `run_match()`: รับชิ้นที่ 1–6 → ผ่าน Check Point 2 จุด (สติกเกอร์เหลือง 50×50) → จบที่ FINISH ตาม `finish_route()`
- เส้นทางเป็นชุดคำสั่ง `("F", ms)` เดินหน้า, `("B", ms)` ถอย, `("L", องศา)` หมุนซ้าย, `("R", องศา)` หมุนขวา เก็บแยกต่อสีในฟังก์ชัน `green_deliver_route()` / `yellow_deliver_route()` / `red_deliver_route()` และ `green_return_route()` / `yellow_return_route()` / `red_return_route()` พร้อม `finish_route()` **คืนลิสต์ว่างไว้โดยตั้งใจ** ถ้าเส้นทางของสียังว่าง หุ่นจะหยุดและขึ้น ✗ แทนที่จะวิ่งเดา ต้องวัด ms บนพื้นจริงที่กำลัง 255 และตั้งองศาจากเข็มทิศก่อนแข่ง
- ตอนเดินตรง `drive_straight()` ใช้เข็มทิศคุมแนวแบบเดียวกับ `find_cans()` ตอนหมุน `turn_in_place()` เบรกที่ `TURN_TOLERANCE_DEG` และมีเพดาน 5 วินาทีต่อการหมุนหนึ่งครั้ง
- อย่าให้ล้อแตะเส้นดำเลย และอย่าให้เซ็นเซอร์พื้นค้างบนเส้นดำเกิน 3 วินาทีตามกติกา การผ่าน Check Point ต้องออกแบบเส้นทางให้ส่วนใดส่วนหนึ่งของหุ่นทับสติกเกอร์เหลือง
- เทสต์จำลองใช้ `python tests/test_search.py` ครอบคลุมการคีบ การหมุนเข้าหาแนว ลำดับปล่อยของ และลูปภารกิจ 6 ชิ้น (ใช้เส้นทางความยาว 65 ms สมมติ)

1. ปิดไฟก่อนย้ายสายเซอร์โวให้ตรงกับผัง S1/S2/S3 ถ้าทุกตัวรองรับ 5V ให้ตั้งไฟกลุ่มพอร์ตที่ใช้ไว้ที่ 5V ตรวจพิกัดกระแสรวมของเซอร์โวขณะรับโหลด เพราะภาคจ่าย 5V ของบอร์ดรองรับสูงสุด 3A รวม [คู่มือ MOTION:BIT Pro](https://cdn.robotshop.com/media/C/Cyt/RB-Cyt-437/pdf/cytron-motionbit-pro-12v-robotics-expansion-board-for-microbit-datasheet.pdf)
2. จัดรางไว้ระดับรับ ลอง S1 แบบปลดโหลดเพื่อตรวจทิศยกและเวลาวิ่งทั้งสองทิศ หากถึงสุดรางก่อนเวลาที่ตั้งไว้ให้กด B แล้วลดเวลา ตรวจท่ากางและมุมหุบของ S2 และ S3 ทีละข้างก่อนขนกระป๋อง
3. ตั้ง NB142 ใต้หน้ารถ หันหัวอ่านลงพื้น ลองทีละช่องบนพื้นผิวที่ต้องการให้หุ่นเดินหน้า วัดขาสัญญาณเทียบ GND ถ้าได้ใกล้ 3.3V ตอนตรวจเจอ ใช้ `NB142_DETECTED_LEVEL = 1` ถ้าได้ใกล้ 0V ตอนตรวจเจอและใกล้ 3.3V ตอนพ้นพื้นผิวนั้น ให้ตั้งเป็น `0`
4. ปรับเทียบเข็มทิศตอนกด A ครั้งแรกตามคำแนะนำบนจอ ตรวจว่าการหมุนขวา 90° เพิ่มค่าทิศใกล้ 90° ในท่าติดตั้งจริง ลองขณะมอเตอร์ทำงานด้วย เมื่อไม่มีการแก้แนวแทรก หุ่นจะเบรกเมื่อวัดมุมหมุนได้อย่างน้อย 86° เพื่อเผื่อระยะไหลถึงเป้าหมาย 90° ปรับค่า TURN_TOLERANCE_DEG ตามมุมที่วัดได้บนพื้นจริง หากเข็มทิศอ่านไม่ได้ หรือหมุนไม่สำเร็จใน 5 วินาที รถจะหยุดและแสดง ✗ หากต้องการยกเลิกระหว่างรอบให้กด B [คู่มือเข็มทิศ MakeCode](https://makecode.microbit.org/reference/input/compass-heading)
