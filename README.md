## ลงโปรแกรมครั้งแรก

### ถ้าจะเปลี่ยนพฤติกรรม ให้แก้ตรงไหน

**ตั้งค่าแขน** เปิด [main.py](./main.py) ในแท็บ Python ของ MakeCode แล้วแก้ตัวเลขหลังเครื่องหมาย `=` ตรงต้นไฟล์ จากนั้นกด **Download** อีกครั้ง ค่า 500 มิลลิวินาทีเท่ากับครึ่งวินาที

| พอร์ต | บรรทัดที่ค้นหาด้วย Ctrl+F | ค่าเริ่มต้น | ค่าที่ใส่ |
|---|---|---|---|
| S1 รางหมุนต่อเนื่อง | `RACK_UP_COMMAND` / `RACK_DOWN_COMMAND` | 75 / 105 | ทดสอบว่า 75 ทำให้เพลาหมุนซ้ายและยกรางจริง หากกลับทางให้สลับสองค่า ค่า 90 ใช้หยุด |
| S1 เวลายก / ลด | `RACK_UP_MS` / `RACK_DOWN_MS` | 500 / 500 ms | วัดเวลาจากระดับรับถึงท่าขน และจากท่าขนกลับถึงระดับวาง |
| S2 คีบซ้าย 180° | `GRIP_LEFT_OPEN` / `GRIP_LEFT_CLOSED` | 40° / 10° | กางไปทางซ้าย ใช้ 10° เป็นท่าหุบ |
| S3 คีบขวา 180° | `GRIP_RIGHT_OPEN` / `GRIP_RIGHT_CLOSED` | 40° / 10° | กางไปทางขวา ใช้ 10° เป็นท่าหุบ |

**ทดสอบแล้วสั่งหุบที่ 45° แต่หุ่นกลับกาง** จึงใช้ 45° เป็นท่ากางและ 10° เป็นท่าหุบทั้งสองข้าง ปัจจุบันลดมุมกางเริ่มต้นเหลือ 40° ตามการทดสอบล่าสุด หากปากคีบชนกระป๋องตอนรับ ให้เพิ่มกลับทีละ 2–3° หากฝั่งใดยังกางตอนสั่งหุบ ให้ไล่เพิ่มค่าหุบเฉพาะฝั่งนั้นทีละ 5° เพราะทิศที่วงเคลื่อนขึ้นกับการติดตั้งก้านเซอร์โวของแต่ละข้าง

**ถ้ากด B ขณะที่แขนกำลังรับ** ล้อและ S1 จะหยุด S2/S3 ค้างมุมล่าสุด ให้ประคองกระป๋อง จัดรางกลับระดับรับ แล้วกด **RESET** เพื่อเริ่มรอบใหม่

เปิด `main.py` แล้วกด **Ctrl+F** ค้นหาชื่อในตาราง ค่าที่ปรับกับหุ่นอยู่ต้นไฟล์ มุมปากคีบใช้หน่วยองศา เซอร์โว 360° ใช้ค่าควบคุมทิศและความเร็ว เวลารอใช้มิลลิวินาที ส่วนคำสั่ง `wait_micros` ของอัลตราโซนิกใช้ไมโครวินาที

| อยากเปลี่ยนอะไร | ค้นหาในโค้ด | วิธีปรับ |
|---|---|---|
| ให้รถเข้าใกล้กระป๋องอีกก่อนหยุด | `PICKUP_DISTANCE_CM` | เช่น เปลี่ยน 10 เป็น 8 เพื่อยืนยันการคีบภายใน 8 ซม. จากหน้าหัว HC-SR04 |
| ระยะเดินหนึ่งช่อง / ระยะเข้าแท่น | `FIELD_TILE_MS` / `DROP_APPROACH_MS` | เริ่มที่ 500 ms ต่อ 30 ซม. และ 400 ms จากช่องหน้าแท่นถึงตำแหน่งปล่อย วัดกับพื้น ลูกระนาด สะพาน และระยะยื่นของก้ามทั้งสองข้าง |
| กำลังล้อ | `SPEED` | 255 คือเต็มกำลัง ค่านี้มีผลทั้งเดินหน้า ถอย และหมุน ถ้าแก้ให้วัดระยะถอยและมุมหยุดใหม่ |
| ความคลาดเคลื่อนตอนเลี้ยว | `TURN_TOLERANCE_DEG` | เมื่อหันตามทิศในผัง ยอมให้คลาดจากทิศเป้าหมาย 4° |
| ความไวในการรักษาแนวตรง | บรรทัด `amount =` และบรรทัด `trim +=` | 2 คือมุมเบนที่ยอมได้, 3 คือกำลังชดเชยต่อองศาที่เกิน, 80 คือเพดานส่วนต่างกำลัง ตัวเลข 16 ในบรรทัดถัด ๆ ไปจำกัดการเปลี่ยนต่อรอบ ลดขนาด 16 ทั้งสองฝั่งถ้าต้องการให้ค่อย ๆ ปรับขึ้นลง |

### นำเข้าและลงบอร์ด

1. เปิด [MakeCode สำหรับ micro:bit](https://makecode.microbit.org/) แล้วเลือก **Import → Import URL**
2. วางลิงก์ `https://github.com/JT8966/can-gripper-robot` แล้วกดนำเข้า
3. เสียบสาย USB ที่ส่งข้อมูลได้จากคอมพิวเตอร์ **เข้าพอร์ต USB บนตัว micro:bit** แล้วกด **Download** ใน MakeCode
4. ถ้าเบราว์เซอร์บันทึกไฟล์ `.hex` ลงคอม ให้คัดลอกไฟล์นั้นไปที่ไดรฟ์ **MICROBIT** แล้วรอไฟด้านหลังบอร์ดหยุดกะพริบ ถ้าจับคู่บอร์ดผ่าน WebUSB แล้ว ปุ่ม Download จะส่งโปรแกรมลงบอร์ดโดยตรง [คู่มือโอนโปรแกรมของ MakeCode](https://makecode.microbit.org/device/usb)

## พอร์ตของหุ่น

| อุปกรณ์ | พอร์ต MOTION:BIT Pro |
|---|---|
| ล้อซ้าย 2 ตัว | ต่อทีละตัวที่คู่ M1A/M1B และคู่ M2A/M2B ทิศเดินหน้าคือ M1A และ M2A |
| ล้อขวา 2 ตัว | ต่อทีละตัวที่คู่ M3A/M3B และคู่ M4A/M4B ทิศเดินหน้าคือ M3A และ M4A |
| รางยก–ลด (360° หมุนต่อเนื่อง) | S1 |
| วงคีบซ้าย (180°) | S2 |
| วงคีบขวา (180°) | S3 |
| HC-SR04 รุ่น 5V แบบ 4 ขา | VCC → ขา 5V, GND → GND, TRIG → P0, ECHO → P1 ผ่านตัวแบ่งแรงดัน |
| MOTION:BIT Pro → PCA9548A | Maker Port I²C: SDA (P20) → SDA, SCL (P19) → SCL, 3V3 → VDD/VCC ของโมดูลที่รองรับ 3.3 V, GND → GND |
| หัวอ่านขวา S3 → PCA9548A CH0 | SDA → SD0, SCL → SC0 |
| หัวอ่านซ้าย S2 → PCA9548A CH1 | SDA → SD1, SCL → SC1 |
| NB142 รุ่นเอาต์พุตดิจิทัล 5 ช่องที่รองรับ 3.3V | VCC → 3V3, GND → GND และเอาต์พุตซ้ายสุดถึงขวาสุด → P12, P13, P14, P15, P16 ที่ขา Signal ของ GPIO |

จ่ายไฟให้หัว TCS34725 ทั้งสองตัวจาก 3V3 และใช้ GND ร่วมกับบอร์ด เลือกโมดูลที่รองรับไฟ 3.3 V ตั้ง A0/A1/A2 ของ PCA9548A เป็น LOW เพื่อใช้ `MUX_ADDRESS = 0x70` ถ้าโมดูลตั้งที่อยู่อื่น ให้แก้ค่านี้ที่ต้น `main.py` หัวอ่านทั้งสองใช้ที่อยู่ 0x29 โปรแกรมเปิดทีละช่องแล้วอ่านกลับเพื่อยืนยันก่อนคุยกับหัวสีนั้น [คู่มือ PCA9548A ของ NXP](https://www.nxp.com/docs/en/data-sheet/PCA9548A.pdf)

**ลดแรงดัน ECHO ก่อนต่อ P1** ต่อ ECHO → ตัวต้านทาน 10 kΩ → จุดร่วมที่ต่อเข้า P1 แล้วต่อจากจุดร่วมนั้นผ่านตัวต้านทาน 10 kΩ อีกตัวลง GND แรงดัน 5V จะลดเหลือประมาณ 2.5V [ผัง HC-SR04 สำหรับบอร์ด 3.3V](https://learn.adafruit.com/ultrasonic-sonar-distance-sensors/pinouts)

### ตั้งระยะและลำดับคีบ

รถใช้ระยะเริ่มต้น `PICKUP_DISTANCE_CM = 10` ซม. เข้าหาชุดหลุมดำครั้งละคู่ โดยจับเวลาเฉพาะช่วงที่เดินเพื่อถอยกลับไปช่องเดิม หากครบระยะประมาณหนึ่งช่องแล้วยังไม่พบวัตถุในระยะสองครั้ง รถจะหยุด หัวสีทั้งสองต้องอ่านได้สีประจำสนามซ้ำสองครั้งห่างอย่างน้อย 65 ms จึงหุบ S2/S3 และยก S1 สีซ้ายและขวาต่างกันได้ ดูค่า `R ... / L ...` ผ่าน USB Serial

เส้นทางประกอบด้วยทิศตามภาพ `N` ขึ้น `E` ขวา `S` ลง `W` ซ้าย หนึ่งตัวอักษรแทนหนึ่งช่อง ดู `START_PATH`, `PICKUP_PATHS`, `station_path()` และ `FINISH_PATH` ใน `main.py` ช่วงส่งไปและกลับผ่านจุดร่วม (6,3) เพื่อให้รถเริ่มแต่ละเส้นจากตำแหน่งอ้างอิงเดียวกัน เดินเข้าหาแท่นตาม `DROP_APPROACH_MS` แล้วถอยออกหลังปล่อย เวลาเดินและยกรางเป็นค่าเริ่มสำหรับซ้อม ปรับที่ `place_raise_ms()` สำหรับเขียว 5 ซม., เหลือง 10 ซม. และแดง 15 ซม. ทดสอบตำแหน่งก้ามเทียบขอบแท่นจริงทั้งแต่ละข้างและกรณีวางสองใบพร้อมกัน

เมื่อถือสีต่างกัน รถส่งใบขวาก่อน แล้วส่งใบซ้าย เมื่อส่งครบทั้งคู่ รางลดกลับระดับรับก่อนเริ่มคู่ถัดไป โปรแกรมใช้เวลาการแข่งขัน 180 วินาทีเป็นกรอบวางแผน และเช็กก่อนเริ่มคู่ใหม่ว่ามีเวลาเหลือเกิน 45 วินาที ลองจับเวลาทั้งรอบจริงเพื่อจูนเส้นทาง

### ทดลองกับหุ่นจริง

1. ปิดไฟก่อนย้ายสายเซอร์โวให้ตรงกับผัง S1/S2/S3 ถ้าทุกตัวรองรับ 5V ให้ตั้งไฟกลุ่มพอร์ตที่ใช้ไว้ที่ 5V ตรวจพิกัดกระแสรวมของเซอร์โวขณะรับโหลด เพราะภาคจ่าย 5V ของบอร์ดรองรับสูงสุด 3A รวม [คู่มือ MOTION:BIT Pro](https://cdn.robotshop.com/media/C/Cyt/RB-Cyt-437/pdf/cytron-motionbit-pro-12v-robotics-expansion-board-for-microbit-datasheet.pdf)
2. จัดรางไว้ระดับรับ ลอง S1 แบบปลดโหลดเพื่อตรวจทิศยกและเวลาวิ่งทั้งสองทิศ หากถึงสุดรางก่อนเวลาที่ตั้งไว้ให้กด B แล้วลดเวลา ตรวจท่ากางและมุมหุบของ S2 และ S3 ทีละข้างก่อนขนกระป๋อง
3. ตั้ง NB142 ใต้หน้ารถ หันหัวอ่านลงพื้น ลองทีละช่องบนพื้นผิวที่ต้องการให้หุ่นเดินหน้า วัดขาสัญญาณเทียบ GND ถ้าได้ใกล้ 3.3V ตอนตรวจเจอ ใช้ `NB142_DETECTED_LEVEL = 1` ถ้าได้ใกล้ 0V ตอนตรวจเจอและใกล้ 3.3V ตอนพ้นพื้นผิวนั้น ให้ตั้งเป็น `0`
4. ปรับเทียบเข็มทิศตามข้อความบนจอ จากนั้นวางรถหันขวาที่ START ก่อนกด A เพื่อให้ทิศในผังตรงกับตัวรถ ทดสอบว่าแต่ละมุมและระยะหยุดตรงกับจุดจริง โดยเฉพาะลูกระนาดและสะพาน

## เทรน AI ให้จำสีกระป๋อง (Decision Tree)

หัวสี TCS34725 สองตัว (ขวา S3 ช่อง 0, ซ้าย S2 ช่อง 1) อ่านค่า RGBC ดิบผ่าน PCA9548A อยู่แล้ว เราเก็บค่าจากกระป๋องจริงทาง Serial แล้วให้คอมเทรน Decision Tree ขนาดเล็กแยกตามหัว แปลงกฎเป็น `if` ใน `main.py` ตอนแข่งหุ่นจึงจำแนกสีเองได้โดยไม่ต้องต่อคอมหรืออินเทอร์เน็ต นี่คือ AI ช่วยตัดสิน **สีของกระป๋อง** ส่วนเส้นทางยังต้องจูนแยกตามปกติ

### 1. เก็บตัวอย่างจากหุ่น

1. ลงโปรแกรม `main.py` ปัจจุบัน แล้วเปิด Serial Monitor (MakeCode แท็บ **Show data** หรือเทอร์มินัล 115200 baud)
2. กด **A+B ค้าง** ตอนเปิดเครื่อง จอแสดงชื่อสี แปลว่าเข้าสู่โหมดเก็บตัวอย่างแล้ว
3. ใส่กระป๋องสีเดียวกันให้ตรงตำแหน่งคีบทั้งสองข้าง ถ้าเก็บสีไหนให้ใช้กระป๋องสีนั้นทั้งคู่
4. กด **B ค้าง** เกิน 1 วินาทีเพื่อหุบ/กางคีบ ให้เก็บตัวอย่างในท่าหุบเหมือนตอนแข่ง
5. กด **A** เปลี่ยนป้ายสี (RED → BLUE → GREEN → YELLOW → NONE) กด **B สั้น** ให้เก็บ 5 ค่า (พิมพ์ 10 บรรทัด ทั้งสองหัว)
6. เก็บสีและ NONE อย่างละอย่างน้อย 20 ครั้ง หมุนกระป๋องให้เห็นพื้นสี ตัวหนังสือ และแสงสะท้อน เปลี่ยนมุมแสงและระยะให้ใกล้ตอนแข่ง
7. กด **A+B ค้าง** อีกครั้งเพื่อออกจากโหมด

Serial จะพิมพ์บรรทัดแบบนี้:

```text
SAMPLE,RIGHT,RED,1043,662,254,151
SAMPLE,LEFT,RED,1011,640,270,143
```

คัดลอกบรรทัด `SAMPLE,...` ทั้งหมดลงไฟล์ `tools/samples.csv` (UTF-8)

### 2. เทรนและเทียบกับเกณฑ์เดิม

```bash
python tools/train_color.py tools/samples.csv
```

สคริปต์ใช้แค่ standard library จึงไม่ต้องติดตั้งอะไรเพิ่ม รายงานจะแยกตามหัวซ้าย/ขวา และบอกจำนวนตัวอย่าง, ความแม่นของเกณฑ์เดิมใน `main.py`, ความแม่นของ Decision Tree, ค่า k-fold CV และตารางทายผิดในแต่ละสี

ใช้โมเดลเมื่อ CV สูงกว่าเกณฑ์เดิมชัดเจน เช่นมากกว่า 5% และทุกสีที่แข่งทายถูกเกือบทั้งหมด ถ้า CV ต่ำกว่า ให้เก็บตัวอย่างเพิ่มโดยเฉพาะกรณีแสงสะท้อน เงา และกระป๋องที่หมุนต่างมุม

### 3. ใส่โมเดลลงหุ่น

```bash
python tools/train_color.py tools/samples.csv --apply main.py
```

คำสั่งนี้จะแทนช่วง `BEGIN COLOR MODEL ... END COLOR MODEL` ใน [main.py](./main.py) ด้วยกฎที่เรียนมา แล้วเปิด MakeCode กด **Download** ลงบอร์ด ครั้งแรกที่คีบ Serial จะพิมพ์ `MODEL TRAINED` หรือ `MODEL THRESHOLD` ให้รู้ว่าบอร์ดใช้โมเดลไหน

- `MODEL_READY = False` คือใช้เกณฑ์เดิมใน `read_color()` ถ้าเทรนแล้วผลไม่ดี ให้ตั้งกลับเป็น `False` หรือใช้ git ย้อนไฟล์
- ถ้าโมเดลทายเป็น `NONE` หรือทายไม่มั่นใจ `read_color()` จะคืน 0 หุ่นจะไม่คีบและขึ้น ✗ ตามพฤติกรรมปลอดภัยเดิม
- ตรวจสคริปต์เทรนด้วย `python tests/test_train_color.py` (ข้อมูลในเทสต์เป็นข้อมูลสังเคราะห์เพื่อทดสอบโค้ดเท่านั้น ต้องเก็บค่าจริงก่อนใช้แข่ง)
